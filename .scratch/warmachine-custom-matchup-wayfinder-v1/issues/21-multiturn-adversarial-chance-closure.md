## Question

怎样把终局导向的严格路线、完整激活候选域和初始状态值代数组合为可恢复的多回合随机博弈，使每个初始状态的我方选择、对手回应、Chance 结果和未展开质量都能被求值，而不是只评价一条双方合作的路线？

## Acceptance

- 我方合法策略选择按 OR/max、对手完整行动与反应按 AND/min、同一随机事件的互斥完备结果按 Chance 精确有理数质量聚合；三类分支身份不可互换或错误求和。
- 对手域须逐步展开完整的合法动作/激活序列及适应性后续选择，不仅是伤害转移等即时选项；整轮激活顺序、控制阶段、资源、场景结算和提前终局均由 Host strict 执行，不要求预先物化所有整轮脚本。
- 反向终局前沿可与从合法部署出发的 strict 正向状态连接；连接必须绑定完整规则状态、时间、剩余资源、规则持续状态和对抗上下文，不能只按位置或模型数合并。
- 搜索同时维护按剩余时域分层的反向目标域与从精确合法开局产生的正向可达域。反向域只提供目标相关约束，正向域只提供真实可达状态；正向后继与下一层反向域无交集时，只有取得必要条件完备证明才可 hard reject，否则只是排序靠后或 unresolved。
- 每个计算批次在相同终局族、Host 收据、时域、候选域和规范状态模式下记录正反两侧的唯一分支因子、约束收缩、strict 调用、汇合精度、内存和 unresolved 率，并据此选择扩正向、反向或双向；方向阈值只能是有收据的校准先验，不能当作普适理论或规则裁决。
- 方向调度显式区分 `strict_witness_discovery`、`denominator_closure` 和 `value_interval_tightening`。第一类可比较每条见证成本；后两类必须比较完整等价单元覆盖增量、连续域/候选/回应/Chance 债务减少量和值区间宽度收缩，不能因快速找到一条合作路线而优先一个仍有大量 unresolved 的方向。要求完整声明域的 `strict_exact` 时最终 unresolved 必须为零；单独数值界相等不能冒充域穷尽。
- Chance 成功、失败、低概率裁剪与 unresolved 质量逐事件守恒；阈值裁剪保留质量且不得重新归一化。
- 搜索支持外存 DAG、检查点、并行和中断恢复；重复状态共享后继计算，但军表、地图、部署、路线、概率来源和对手上下文保持独立标签。
- 至少一个有限微型状态达到 exact 值；固定 Sepsira/Fane 的真实 100 点初始格可以保持区间，但必须显示已闭合候选/回应/概率分母以及导致上下界仍开放的具体债务。
- 同一有限 benchmark 必须对照纯 fixed-start strict 正向、纯符号反向与反向目标域引导的 strict 正向/双向连接；分别覆盖选择性强的刺杀终局和多项合取的场景得分终局，不能用单条更快见证替代动作域完备比较。
- 输出可直接被 Ticket 09/10 消费，并明确区分策略值、已发现路线概率、筛选指标和用户声明初始分布。
- 多回合展开必须消费 Ticket 22 已认证的目标策略商；任何不在反向包络中的规则行为单元若没有不可达、交替支配或上下界证书，必须继续作为正向补集债务，不能因反向未命中而省略。
- 调度成本分成符号证明、Host 单步 strict 和多回合 strict 根三账。有限对照已证明策略商可用额外状态对计算换取后续根缩减，但真实层只有在同任务/同分母测得总成本和债务均改善时才采用；小域允许直接纯正向闭合。

## 对手回应合同（2026-09-05）

以下是21a/21b的开发合同，不是本轮已经实现的执行功能。数学依据见[原理审计](../../../docs/research/ticket-search-principles-audit-20260905.md)，参考[PRISM-games 的对抗可达目标](https://www.prismmodelchecker.org/games/properties.php)和[PET2 的可靠部分求值](https://link.springer.com/chapter/10.1007/978-3-031-65633-0_16)；具体接口和验收设计是本项目的应用推论。

### 查询与量词

- 路线查询：给定某个终局条件，寻找存在的合法历史与条件成功概率。这是反向搜索本来的见证用途，保留，不伪称能强制对手配合。
- 对抗查询：在任务明确的有限时域、军表/部署域和信息条件下，我方采用最优应对策略，对手采取最不利合法回应时，完成任务目标的概率及可靠区间。固定题默认这个口径，不靠LLM预测对手。
- 策略是“观察到某状态后选什么”的分支策略，不是预先固定双方每一步的脚本。我方可根据对手已经发生的动作与已揭示骰值改变后续计划；双方均不能预知未来骰值。
- 对给定任务目标G，值是 `sup(我方策略) inf(对手策略) P(时域内达到G)`。收益以查询方固定视角解释：我方选择取max，对手选择取min，随机结果按Host支持集与条件概率求和。不能把主动方身份当作恒定max，也不能把所有反应都当作min。
- “恰好在第三回合”和“不晚于第三回合”是不同查询；和局、对手先胜、时域用尽如何赋值写入任务。第一版限定已声明的可观察信息；未支持的隐藏/同时选择语义保持未认证，不用普通顺序max/min假装解决。

### 终局根与任务目标

单个预设根是探索入口，不是全部胜利方式。对手避开某个刺杀位置后，可能存在另一位置的刺杀，也可能让出任务得分。若任务目标是“时域内获胜”，后继仍按Host实际胜利条件求值；若任务只询问指定根，则明确报告该根的条件结果。

刺杀/得分根归入同一个查询后，在共享状态与互斥随机事件上计算目标并集。一个终态被多个根描述不重复累计概率；分别对每个根取min再加总，不等价于对共同获胜目标取min。尚未覆盖的其它可能获胜终态也保留发现域债务。

### 按时间轴展开

1. Engine先判断当前合法窗口及真实终局。Host已完成终局结算时停止，不再添加死后反击；单凭Leader零血不能跳过Tough、替代及真实终局判定。
2. 当前动作中的反应、转移、替代、目标/落点和同时效果排序，按Host声明的选择方与信息揭示顺序逐个生成。可选效果才允许decline，强制结算不是玩家策略分支。
3. 每一选择或随机结果strict执行后重建状态，再查询下一个窗口。前一回应移走/摧毁模型、改变资源或授予能力时，不能继续使用旧选项列表；只有证明独立的选择才可一次性做笛卡尔积。
4. 跨入对手回合后，控制/资源、完整激活次序、移动、施法、攻击、控场与计分均继续展开。不额外强迫对手进攻或交换；守住、后退、放弃动作是否可用由Host决定。
5. 返回我方后保留适应性选择，直到终局或声明时域。不在每层重新固定一条同样的计划，也不把层外的潜在长线胜利解释为不可能。

### 部分探索与剪枝

复用08的值代数。未枚举对手选项且没有其它证书时，该对手节点下界为0；已探索分支可给更低的上界。未知我方动作同理保留上界1。将原有输入布尔闭包逐步接到20/22的真实域证据，而非靠调用者手工声明完整。

Chance保留每一事件的条件质量，未展开质量m贡献区间 `[0,m]`，不重新归一化。不同策略不是随机事件，不能给对手各行动平均分配概率；固定某个外部对手策略分布是另一个命名查询，不能冒充最不利对抗值。

优先展开可能破坏当前保证的回应和影响区间最大的未决项，同时保留公平的补集游标；优先顺序只改变先算谁，不是永久剪枝。硬剪枝须有Host非法/必要条件矛盾、22的等价/交替支配或可靠区间证书，不能按静态战术分数或“不在胜利路线中”删去。

先用严格递减的事件/步数秩构成有限微域。只有回合上限而存在未建模的回合内循环时，报告未解析，不把循环当失败，也不靠数值不再变化宣称收敛。预算/区间精度停止与“全部合法域已展开”分别记账；区间证据即使精确也不能伪造域穷尽标志。

### 既有实现复用与缺口

- `initial-state-adversarial-value-v2` 已对不完整对手集合给出保守下界；这是基础求值，不能把输入的`responseSetComplete=true`当自动证明。
- `opponent-response-v1` 有伤害转移的有限选项；`opponent-response-domain-v2` 保留当前Host投影的反应选项，并明确连续落点、反应顺序、反应Chance及复合转移的未闭合标志。其“当前动作无即时回应”不等于“后续整个对手回合无回应”。
- `goal-conditioned-strategy-quotient-v1`已有隐藏反制、不同分布和反向漏解的小域反例；本工单复用，不另写规则裁决器或概率基础库。
- 本轮只修改计划与验收。多回合生产展开、任务级认证及上述完整R21矩阵仍待实现/待验收。
