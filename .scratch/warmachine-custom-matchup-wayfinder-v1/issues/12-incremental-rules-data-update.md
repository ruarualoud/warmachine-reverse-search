# 建立规则与卡牌更新的增量重建流程

Type: task
Status: open
Blocked by: 03, 04, 05
Part of: ../map.md

## Question

当新卡、配装、规则文本、原子、钩子、场景或 Host 代码更新时，怎样只重建受影响的军表、需求组、终局根、反向路径和值报告，并证明未受影响证据可以安全复用？

## Acceptance

- 复合收据分别绑定数据、Force Builder、Host、原子/钩子、interaction graph、场景和搜索配置。
- 语义影响索引能区分纯构筑变化、既有原子复用、新语义、规则执行变化和场景变化。
- 只有依赖闭包未变且内容哈希一致的军表池、终局根、路径和报告可复用；其它证据 fail-closed 失效。
- 新增卡若复用既有原子仍需真实卡牌 strict 正反场景；新增语义在实现前保持规则未知。
- 用一次模拟构筑变化和一次规则原子变化证明增量重建范围、旧检查点拒绝和最终报告更新。
