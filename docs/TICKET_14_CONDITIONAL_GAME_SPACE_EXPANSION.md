# Ticket 14：条件对局空间扩充与可证明折叠

## 目标

在 Ticket 13 的产品完成门之后，为**已声明条件**的 Warmachine 对局建立可渐进扩展、可恢复、可审计的状态—动作—机会空间。该 Ticket 的目标不是把有限搜索宣传为真实游戏的全局完备解，而是让系统能够在用户确认的条件模型内，持续报告已枚举空间、经证明折叠空间、支配剪枝空间、未展开质量与仍需补充的场景。

> **条件对局空间**是指规则收据、双方阵容、场景、地图、地形、部署、先后手、骰子机会模型、几何离散化、回合上限和允许策略集合全部固定后的有限模型。任何一个条件改变都必须生成新的空间身份与新的覆盖账本。

## 前置依赖

| 依赖 | 要求 |
|---|---|
| Ticket 05 | 终局任务计划、checkpoint、处置守恒与 receipt 漂移拒绝可用。 |
| Ticket 06–07 | 至少一条刺杀和一条得分路线可从合法部署严格重放。 |
| Ticket 08 | Chance 节点质量守恒、AND/min 对手节点、未展开上界和值区间可用。 |
| Ticket 11 | 搜索动作能消费已映射的阵营独有机制，未知规则仍 fail-closed。 |
| Ticket 12 | 规则/数据变化能定向失效受影响空间证据。 |
| Ticket 13 | 聚合门能验证纵向、跨阵营、恢复、漂移和浏览器证据。 |

## 条件模型身份

每次扩充必须生成 `conditionalGameSpaceId`，其密封核心至少包含下列字段；所有 checkpoint、节点、值区间和报告均绑定该身份。

| 轴 | 必填内容 |
|---|---|
| 规则 | Host receipt、Construction Host receipt、原子/交互版本、规则来源状态。 |
| 阵容 | 双方完整 roster、领袖/副本/配装、阵营与阵营特殊机制。 |
| 场景 | Steamroller 场景、目标物/地形语义、地图模板、地形布置、部署种子。 |
| 开局 | 先后手、部署、初始资源、当前回合、已知历史与生命周期状态。 |
| 几何 | 有限锚点集、角度/距离分辨率、碰撞和 LOS 模型、允许的移动生成器版本。 |
| 机会 | 掷骰分布、重掷/修正、未声明概率时的区间口径。 |
| 策略 | 双方允许动作族、对手节点求解规则、回合上限、截断与界的定义。 |

任何条件轴缺失时，系统只能产出 `scope_incomplete`，不得生成“完整”或“最优”结论。

## 分层扩充与折叠

扩充按层执行，每层均须在上一层的密封空间上追加，不得静默修改先前节点语义。

| 层级 | 扩充对象 | 可接受的折叠 | 证明要求 |
|---|---|---|---|
| L0 | 规范化合法状态与动作 | 无 | 严格状态/动作 receipt、机会质量守恒。 |
| L1 | 地图对称 | 仅保留保持双方、目标物、地形、部署与行动语义的地图自同构轨道代表元 | 显式自同构映射、状态/动作双向映射、回放等价哈希。 |
| L2 | 可交换模型 | 同侧且卡牌、规则、损伤、资源、状态、位置类别、激活资格完全等价的模型置换 | 置换群、动作映射、终局和资源守恒等价。 |
| L3 | 几何/拓扑类别 | 经声明有限化后具有相同碰撞、控制、LOS、可行动集与目标关系的空间单元 | 边界样本、单元不变量、跨单元拒绝证据和几何版本哈希。 |
| L4 | 支配剪枝 | 信息集相同且一方动作集包含另一方、资源/位置/终局单调关系被规则证明的节点 | 支配方向、反例搜索、对手响应保留、值界不变证明。 |
| L5 | 场景矩阵 | 用户确认的阵容×场景×地图×地形×部署×先后手组合 | 矩阵分母、每格证据状态、跨格不可外推声明。 |

**不得折叠**的状态包括：不同隐藏/延迟触发历史、不同规则来源状态、不同资源支付时点、不同可用反应、不同控制权、不同连续效果、不同机会分布，或任何尚未证明行为等价的几何状态。

## 可恢复分块搜索

空间扩充采用确定性任务块而不是大批量内存枚举。每个块必须包含：

1. `frontierCursor`：规范化节点排序中的恢复游标；
2. `conditionalGameSpaceId` 与层级版本；
3. 节点输入/输出哈希、折叠证书、支配证书或未展开原因；
4. 已消费和剩余的机会质量；
5. 块级资源计量，但**资源计量不得改写节点处置**；
6. 原子 checkpoint，任何中断只重做未提交块。

单块可以暂停并恢复；`paused_resource_guard` 只能表示未完成工作，不能被统计为拒绝、不可达、输局或零概率。

## 覆盖与结论口径

每个报告必须同时给出下列质量，并明确它们不等同于真实游戏全空间：

| 质量桶 | 含义 |
|---|---|
| `enumerated_exact` | 在当前条件模型中已逐节点严格展开和回放的质量。 |
| `quotiented_exact` | 由有效等价证书折叠、可恢复映射到代表元的质量。 |
| `dominated_with_proof` | 由双向动作/响应和价值界证书安全剪除的质量。 |
| `pending_source_or_rule` | 缺少来源或 Host 规则语义，必须 fail-closed。 |
| `pending_scenario_choice` | 需要用户决定是否纳入的场景矩阵格。 |
| `unexpanded_budget` | 已知但尚未消费的合法前沿质量。 |
| `rejected_strict` | 已由严格规则证明不合法的质量。 |

只有当 `pending_source_or_rule = 0`、`unexpanded_budget = 0`，且所有用户确认的矩阵格均有 `enumerated_exact`、`quotiented_exact` 或 `dominated_with_proof` 覆盖时，系统才能称为：

> **“在声明的条件模型与声明的几何/策略有限化下已闭合。”**

这仍不得表述为真实 Warmachine 的全局最优解，除非用户明确选择的条件模型就是所讨论命题的完整定义。

## 用户协商点

系统必须在以下节点暂停扩展并生成可审阅建议，而不是自行扩大结论范围：

1. **初始条件确认**：阵容、版本、场景、地图、地形、先后手、几何分辨率和回合上限；
2. **覆盖缺口审阅**：展示未覆盖矩阵格及其预计机制增量；
3. **对称/等价争议**：若折叠需要未被规则证明的行为等价，则请求用户选择“保守展开”或“排除该格”；
4. **扩大场景**：用户选择纳入新的地图、地形、部署或对手阵容时，创建新条件模型身份；
5. **结论发布**：用户确认欲报告的是局部路线、条件值区间，还是当前条件模型内闭合结论。

## 验收门

Ticket 14 完成至少需要下列可自动验证证据：

1. 一个小型有限条件模型具有**未折叠基线**与 L1/L2/L3 折叠后基线，二者经映射回放得到相同终局类别、机会质量和值区间；
2. 每个对称/可交换/拓扑/支配折叠都有可验证证书，任一证书缺失时节点回到未展开前沿；
3. 改变任一条件轴、几何版本、规则 receipt 或策略边界，旧 checkpoint 和折叠证书 fail-closed；
4. 已知反例涵盖不对称目标、不同隐匿/持续效果历史、资源支付时点和非等价地形；这些反例不得被折叠；
5. 覆盖报告的所有质量桶加总回到声明的条件空间分母，并对 Chance 质量守恒；
6. 用户选择新增场景格后，仅新增格与受影响等价类重建，原有未受影响证据可复核复用；
7. 报告中不存在“全局最优”“真实胜率”“完整游戏解”等越过条件模型边界的语句。

## 与 Narro 对 Cryx 的关系

Ticket 14 是 Narro 对 Cryx 可求解性评估的必要能力，而不是直接给出优劣的捷径。Narro/Cryx 分析必须先创建明确 `conditionalGameSpaceId`，至少声明双方 roster、领袖、场景/地图/地形、先后手、几何离散化和机会口径。随后才能报告：局部严格路线、已覆盖条件格、未展开质量与条件值区间；只有在用户确认矩阵闭合后，才可报告该条件模型内的对抗结果。

## 团队边界

| 模块 | 责任 | 禁止事项 |
|---|---|---|
| Engine | 几何、规则、动作、机会和状态语义 | 不直接定义搜索折叠等价。 |
| Search Core | 空间身份、前沿、块 checkpoint、AND/min 节点和值界 | 不伪造规则来源或跳过 strict replay。 |
| Quotient Layer | 对称、置换、拓扑与支配证书 | 不以启发式相似度替代证明。 |
| Scenario Matrix | 条件格登记、覆盖分母、用户扩展建议 | 不把未选择的场景外推进结论。 |
| Reporting/UI | 质量桶、证书链接、用户协商点 | 不将条件结论改写为全局优劣。 |

## 非目标

- 不在未声明有限化前枚举连续几何的真实全空间；
- 不用 Monte Carlo 或评分排序替代严格可达性/对手应对证明；
- 不将 budget、来源未决或用户未选择的场景计入严格拒绝；
- 不在本 Ticket 内输出 Narro 对 Cryx 的全局胜率或推荐。
