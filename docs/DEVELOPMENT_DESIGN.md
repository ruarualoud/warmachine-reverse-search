# 开发设计

## 1. 问题定义

目标不是在连续、随机、对抗的完整 Warmachine 状态空间中证明全局最优，而是在用户声明的军表/阵营/场景/地图/预算域内，枚举有代表性的胜利终局，找出可严格认证的到达路线，并把未闭合部分保留为可解释值区间。

固定验证题是 `100` 分 Master Necrosurgeon Sepsira、六队 Mechanithrall Swarm 和六个 Warden 核心，对 Fane of Nyrro 四名领袖及不同合法军表、地图、部署与先后手。实现必须通用支持其它阵营。

## 2. 为什么是混合搜索

纯正向搜索在开局面对大量合法但与目标无关的动作；纯具体反向搜索又会在连续位置、历史损失、随机和可选触发上爆炸。当前方案采用：

- 终局条件化的符号反向回归，优先保留与胜利义务相关的变量；
- 对称、单位置换、拓扑和行为签名的有证据等价合并；
- 每一步前驱由 Engine strict 正向执行认证；
- 部署、精确移动路径、底盘碰撞、激活顺序、随机和反应使用局部正向连接；
- 中间相遇后进行从合法开局到终局的独立完整重放。

反向部分产生好候选，不产生规则真值；正向部分证明候选可执行，不证明未发现路线不存在。

## 3. 状态与终局

终局根不是“第一回合从部署区刺杀”。它描述第 `2–7` 回合中的一个胜利动作前状态，包含：

- 双方真实军表和已损失模型；
- 多血模型剩余生命、系统/分支损伤与状态；
- 模型连续坐标、朝向、底盘、编队和地形关系；
- 当前玩家、轮次、激活历史和剩余动作窗口；
- Focus/Fury/corpse/soul/hunger 等资源；
- upkeep、animi、feat、buff/debuff、控制和反应状态；
- 历史比分、场景控制、计分窗口与胜利合同；
- 需要执行的动作、随机结果和对手选择。

终局可添加与结果无关的模型，但噪声必须有有限生成策略和质量账；不能把“所有模型满血都在场”当作唯一历史。

## 4. 军表与配装生成

军表生成分两层：

1. Force Builder 保证点数、数量、领袖、战斗群、附件、武器/战兽配装和阵营约束合法。
2. 终局需求组提供目标驱动宏型，如刺杀投送、反群体、场景驻守、资源支持、反应/保护和长线续航。

宏型评分只安排有限预算，不删除无法证明支配的合法军表。配装必须逐副本建模，因为能力和分数都会改变终局可行性。

## 5. 几何、移动与激活

移动不能只检查距离。strict 认证必须包含路径折线/曲线、沿途底盘扫掠、模型和地形阻挡、结束摆放、编队、朝向、特殊位移、Massive/不可位移、run/charge/trample/reposition 等动作窗口。反向搜索保存路径义务；若无法逆算，保留 unresolved 并交给有限局部正向连接器。

激活顺序是状态的一部分。一个模型先移动可能为后续模型打开路线，也可能失去 buff、通道或控制范围，因此不能把可交换动作默认视为等价。

## 6. 生命周期与关联规则

伤害后的 disabled、boxed、destroyed、RFP 是分开的有序阶段。Tough、Killing Spree、corpse/soul 生成、替换、爆炸、复活和移除规则可能介入不同阶段。反向原语必须按钩子回归，并通过 interaction graph 找到相关规则；文本关键词相同不构成执行证明。

卡牌获得临时规则时，状态保存来源、目标、持续时间和叠加合同。Stealth 不只检查 True Sight，还可能与 LOS、射程、Spray、Magic Ability、间接效果和目标限制交互，因此依赖闭包按钩子/条件建立，不用一对一硬编码表。

## 7. 概率、对手与剪枝

Chance 节点保存每个等价结果的条件概率和累计概率。概率低于用户声明效率门的分支可以延迟或裁剪，但其质量必须保留，不能重新归一化后假装完整。

对手选择使用 AND/min 或声明的对抗合同。未展开对手回应使上界保持开放。搜索可用以下有证据界限剪枝：

- 规则/资源/距离/轮次不可达；
- 乐观伤害或得分上界仍不足；
- 已有状态在同一义务下 Pareto 支配候选；
- 经证明的对称/单位置换/拓扑等价；
- 概率或效率低于用户门限，但保留裁剪质量；
- CEGAR 从精确 Host reject 提炼的局部不可行约束。

策略偏好、LLM 评价和构筑分数不能作为规则不可达证明。

## 8. 外存 DAG 与恢复

节点按规范状态/义务/Host receipt 内容寻址；边保存动作、概率、玩家选择和 strict receipt。批任务通过 lease、checkpoint 和幂等写入恢复。重复状态共享结构，但军表、地图、部署、路线成本和终局来源标签不得丢失。

Git 不存大型 DAG。生产运行上传不可变工件并在 Git 报告中保存哈希、schema 和重建命令。

## 9. 值与报告

只有 Chance、对手、假设和 strict replay 都闭合的初始状态才有精确值。其它状态输出 `[lower, upper]`：已证明胜利抬高下界，未展开分支保留上界。聚合胜率必须有用户声明或实证初始状态分布；否则按初始格展示。

控制台支持选择胜利场景、注入 Host 审核的人工作为种子、暂停/恢复搜索、逐步回放、兄弟分支切换、真实地图/棋子、值区间和处置守恒。中文结论必须可点击回到 strict 路线或标为筛选假设。

## 10. 更新维护

Engine 更新后重新计算数据、Force Builder、规则、原子、钩子、interaction graph、场景和搜索配置的复合 receipt。通过依赖闭包只使受影响军表池、终局根、路线和值失效。新卡即使完全复用已有原子，也要有真实卡牌正反 strict 场景；新语义在实现前保持 `source_unresolved`。
