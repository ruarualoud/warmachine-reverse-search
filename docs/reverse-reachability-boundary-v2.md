# Warmachine 反向可达性边界 V2

## 核心问题

给定一个后继状态或终局义务，反向核心只求前驱关系：哪些前驱状态、动作、随机结果与反应顺序，经当前 Project D rules-v1 strict 转移可以到达该后继。

它不判断交换、保持位置、阻拦、撤退、得分或进攻哪个更好。它们是并列的后继类型。所谓“主动交换”只能是某个指定后继的一条可达性见证，不是搜索偏好，也不是固定基准必须发生的行为。

## 输出状态

- `strict_reachable_witness`：有绑定当前 Host 收据的 strict 正向转移见证。
- `strict_rejected`：当前精确状态与动作被 rules-v1 strict 拒绝。
- `unresolved_reachability`：尚无完整逆算子或 strict 见证，不能判定不可达。
- `deferred_by_budget`：仅因分页或预算尚未展开，仍属于 unresolved。

反向核心没有“策略差”“交换亏”“价值低”或“被战术支配”的处置状态。

## 候选顺序

候选只按稳定候选身份排序并分页。动作数、证明成本和 Host 调用成本可以决定调度批次，但不改变候选的可达性处置。材料交换、场景压力、预期收益、LLM/Skill 判断和人工战术标签不得影响反向候选集合、顺序或 strict 拒绝。

若预算不足，所有未展开候选必须逐项或按可审计游标记录为 unresolved；不得把它们记成已剪枝失败。

## 层次边界

1. 反向层生成终局义务、符号前驱和 strict 可达性见证。
2. rules-v1 Host 独占合法动作、状态转移、随机、反应和规则真值。
3. 可选的正向对抗或策略层可以消费已认证候选，比较交换、阻拦、撤退和后续回复。
4. 下游策略评价不能回写反向可达性、规则真值或训练真值。

`src/search/efficiency-policy-v2.mjs` 与 `src/search/matchup-search-v1.mjs` 因兼容旧实验继续存在，但属于下游分析，不是 V2 反向核心。`src/reverse` 的自动门禁禁止依赖这些模块。

## 当前证明

`verify-reverse-reachability-contract-v2.mjs` 证明：

- 交换、原地保持和撤离作为并列候选存在；
- 颠倒所有策略标签不会改变候选集合或顺序；
- 分页遗漏只变成 `deferred_by_budget`；
- 反向源码不导入战术评分、对抗搜索或正向补全模块。

固定 Cryx/Fane 基准进一步从同一前驱状态 strict 执行了“攻击 Strygon”和“原地完成激活”两种后继。该证据只证明两者可达，不比较优劣。
