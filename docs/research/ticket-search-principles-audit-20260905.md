# 搜索原理与 23 个工单的优化审计

日期：2026-09-05。审计基线：独立 Search 仓库 `codex/post-audit-mainline-recovery`、Engine 数据 40049。本次是代码与计划审查、补充文献调研及有限回归，不是全游戏正确性或复杂度证明。

## 结论

保留现有“终局约束反推、Host 执行认证、正向补集挑战、随机博弈求值”的方向，不重写搜索器。真正需要调整的是展开与验收顺序，以及如何证明未展开部分不会影响结论。

- 不应把所有规则、所有几何类、所有策略类全部完成作为任何局部求值开发的前提。允许在明确任务范围内逐渐收紧上下界；未知规则、未知对手回应仍阻断相应的精确声明。
- 不应把“反向没找到”作为不可达证明。只有必要条件矛盾、已认证等价/支配或有误差预算的界剪枝才能关闭分支。
- 不应把一条刺杀成功路线的概率作为开局胜率。对方可避开的路线可以具有很高条件成功概率，但对抗保证仍为零。
- 目前确有可复用的求值、外存、恢复、几何证明和部分序模块。新增任务应扩展这些模块，不再平行建设第二套执行器/状态仓库/规则解释器。
- 文档存在真实漂移：公开 DEVELOPMENT_PLAN 仍是 18 个工单；权威地图已有 23 个；地图的 Ticket 23 仍写 5/12，而日志已是 8/12。此次只纠正文档，不虚增完成数。

## 理论依据及适用边界

1. **按需随机博弈求值**。PET2 维护可靠上下界，在部分状态上展开和反传；循环区域另行处理。它说明“完整建图后才能开始求值”不是数学上的必需条件，但没有证明 Warmachine 的状态空间很小。[Meggendorfer & Weininger, CAV 2024](https://link.springer.com/chapter/10.1007/978-3-031-65633-0_16)
2. **可靠停止准则**。普通值迭代前后变化小，并不保证距离真值小。应使用有证明的区间宽度，而非“结果几轮没变化”结束搜索。[Baier et al., CAV 2017](https://www.prismmodelchecker.org/papers/cav17ii.pdf)
3. **符号与几何分离**。PDDLStream 把离散规划与黑盒几何采样器连接，按需兑现乐观符号方案。可借鉴延迟几何验证，但采样完整性有假设，也没有覆盖双方对抗量词。[Garrett et al., ICAPS 2020](https://ojs.aaai.org/index.php/ICAPS/article/view/6739)
4. **冲突回流**。逻辑几何规划可复用失败约束，避免反复求解相似不可能方案。适合把某组碰撞/资源/时序冲突作为可复用排除条件，前提是冲突证据的适用域完整。[Ortiz-Haro et al., ICAPS 2022](https://ojs.aaai.org/index.php/ICAPS/article/view/19811)
5. **双向并非普适更快**。NBS 在特定确定性启发式图搜索假设下给出展开界；不能把该界套到随机对抗、连续坐标和规则未闭合的任务上。方向仍需同任务实测。[Chen et al., IJCAI 2017](https://www.ijcai.org/proceedings/2017/69)
6. **逐渐扩展策略池**。XDO 支持用最佳回应扩展受限策略集。可作为军表/策略候选池的设计来源，但其收敛假设涉及回应求解质量；少量代表军表对打不等于全种族最优。[McAleer et al., NeurIPS 2021](https://arxiv.org/abs/2103.06426)
7. **目标的数学含义**。PRISM-games 区分有限步可达概率、奖励、多目标和双方目标；部分无界奖励还要求停止性。界、步数和目标必须成为查询内容，不能只是报告上的备注。[PRISM-games 官方属性说明](https://www.prismmodelchecker.org/games/properties.php)
8. **增量依赖**。构建系统研究提供动态依赖及可复用构建的设计基础。搜索还需记录“查询过但不存在”的能力域：新单位会增加候选，即使旧路径从未执行新原子，也可能使旧完整性结论失效。[Mokhov et al., ICFP 2018](https://www.microsoft.com/en-us/research/publication/build-systems-la-carte/)

以上是方法来源。下述任务拆分、概率账及工程顺序是针对本仓库的设计推论，不是上述论文已验证过本项目。此前研究中的有限商存在条件继续有效，见 `strategy-quotient-search-optimization-academic-v2.md`。

## 建议的求值合同

每个任务先冻结 `ruleset + rosterDomain + map + deploymentDomain + horizon + objective + geometryPrecision + tolerance`。明确是“在第三回合取胜”还是“不晚于第三回合取胜”，以及和局/时域用尽的值。这些都是状态、缓存与报告键的一部分。

对同一任务声明的有限状态域，设真实值在 `[L(s), U(s)]`：

```text
终态：按任务目标赋精确值；尚未辨明的叶子为 [0,1]
随机：L = sum(p_i * L_i)，U = sum(p_i * U_i)
我方：L = max(L_a)，U = max(U_a)
对方：L = min(L_a)，U = min(U_a)
```

动作域尚未闭合时，额外保留未枚举动作的区间。未知我方动作通常使上界仍为 1；未知对手动作通常使下界仍为 0。不能只在已发现动作中取 min/max 后宣称保证。规则缺失也不能假定等同于一个已知随机失败。

对固定一个随机事件，概率互斥且和为 1。若未展开质量为 `m`，只能把它贡献为 `[0,m]`；不能丢弃后重新归一化。整图存在共享后继和策略分叉，不能把不同策略路径的概率简单加总为全局裁剪预算。

剪枝标准：我方某动作的可靠上界不高于另一动作的可靠下界，可以从当前单目标最优求值中不再展开；对方节点方向相反。若产品要列出所有等优策略，等号不能删除其身份与路线，需保留等优索引。效率阈值是用户限定的搜索域，不可冒充规则不合法或无条件策略支配。

同一轮可以反复施加无资源动作时，回合上限不能自动证明有限步。第一阶段要求严格递减的步数/事件秩；遇到未建模循环报告 unresolved。以后才接循环分量求值，不能直接套 DAG 递推。

## 几何、组合与存储

- **先约束后坐标**：反向保留命中区间、射程、碰撞走廊、同队接触、触发事件顺序等变量约束，按需向 Host 请求具体见证。不能只存终点，模型交换激活顺序也要遵守全状态依赖。
- **三种证明分开**：一个合法坐标见证；一个量化坐标域遍历完毕；一个物理连续区域行为等价。这三种不可互相代替。48 英寸棋盘按 0.01 英寸含边界的中心网格有 `4801^2 = 23,049,601` 个点，尚未扣除底盘边界；多模型笛卡尔积远大于这个数。它是容量示例，不是现有任务实测成本。
- **按需比较等价类**：先按玩家、时域、信息、查询和可观测规则签名分组，再比较相关状态对；对无环小域用后继签名归并。当前全状态对最大不动点保留为微型 oracle，不必直接扩大到全局。
- **缓存排除条件**：保存可复用的最小冲突及依赖对象，例如两个特定底盘阻挡特定通路。不能把一次具体位置冲突扩大成整支单位永远不能完成任务。
- **标签不复制状态**：外存 DAG 已有，继续共享精确状态和后继，军表/部署/路线概率来源单独存标签。几何等价证书不意味着可合并不同对手信息或随机分布。
- **查询驱动的多目标**：胜利概率、得分门槛可以是优化/约束目标；用于讲解的击杀数和剩余资源不必全成为 Pareto 轴。需要多目标时由用户显式选择，保留取舍，不能偷偷用一个战术分数砍掉路线。
- **构筑竞争**：逐步扩展有限合法军表池、查找针对当前策略组合的回应；无法得到全域回应上界时，只报告池内比较。先后选军表和同时选军表是不同博弈。
