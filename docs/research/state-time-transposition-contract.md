## Host 事实审计

对 Cryx/Fane 固定题的一份真实 106 模型房间执行
`buildWarmachineRulesV1StateFromLayer3Room` 和 `normalizeRulesV1State` 后：

- 规范化状态有 65 个顶层字段。
- 106 个模型均被保留；模型字段并集为 307 个。
- 模型字段中至少有 39 个激活、回合或一次性使用字段，20 个生命周期字段，49 个资源字段，19 个控制/单位关系字段，28 个动态规则或状态字段。
- rules-v1 源码直接读写 77 个顶层名称。其中 16 个是输入兼容别名或派生入口，均能落到 65 个规范字段；本轮没有发现无法解释的直接顶层名称。
- 顶层存在二十余种未结算窗口或 continuation stack。不同窗口即使棋盘、生命和资源完全相同，也可能拥有不同合法动作，不能汇合。
- `metadata` 同时保存运行态、输入兼容数据、覆盖声明和静态分析说明。整份 JSON 既不是最小规则状态，也不是可直接信任的 transposition key。

这只证明了直接顶层访问与 normalizer 的第一层对齐。嵌套字段、动态规则读取、适配器派生和未来新增字段仍需专门 verifier，不能据此宣称状态投影已经完备。

## 理论边界

### 状态等价

[Givan、Dean 与 Greig 的 MDP 模型最小化研究](https://cs.brown.edu/people/tdean/publications/archive/GivanetalAIJ-03.pdf)把可安全聚合的状态建立在后续奖励和转移行为等价上。映射到本项目，硬汇合至少要求：同一规则上下文中，两局面对每个合法动作具有相同合法性、终局判断和结果分布。

工程上不直接计算完整双模拟关系，而采用保守投影：投影可以暂时多保留字段、少汇合，但不得漏掉会改变未来的字段。

### 历史状态化

[Rewarding Behaviors](https://cdn.aaai.org/AAAI/1996/AAAI96-172.pdf)和[Structured Solution Methods for Non-Markovian Decision Processes](https://auld.aaai.org/Library/AAAI/1997/aaai97-018.php)表明，历史依赖的转移或收益要通过增加状态变量转成 Markov 状态。对应 Warmachine：feat 是否使用、每回合/每激活次数、计分历史、进入游戏轮次、持续效果期限、移除阶段和未结算选择，只要会影响未来，都必须进入规则状态。

主动兑换的战术意图、路线说明和训练来源不会改变 rules-v1 的未来行为，应保留在路线记录中，而不是污染规则状态。

### 多路径标签

[Martins 的多准则最短路研究](https://doi.org/10.1016/0377-2217(84)90077-8)使用多标签保存非支配路径。相同规则状态可以共享后续计算，但不能把到达它的概率、回合距离、交换代价、容错和未解析质量压成一个标量。每个共享状态节点应挂一组非支配路线标签。

### 对称与动作换序

[状态规划中的对称约简](https://ojs.aaai.org/index.php/AAAI/article/view/8014)和[规划中的偏序约简](https://arxiv.org/abs/1106.5427)支持压缩可互换模型和可交换动作顺序，但前提是证明变换保持转移结构，或动作确实独立。Warmachine 的阻挡、光环、单位一致性、触发顺序和场景存在会频繁破坏这种独立性，因此：

- 对称只用于已经证明的模型置换或棋盘变换。
- 偏序约简只用于读写 footprint 证明互不改变合法性、结果和终局的动作。
- 未证明的拓扑相似或几何近似只能排序，不能硬合并。

### 哈希

[Zobrist 的原始游戏哈希报告](https://research.cs.wisc.edu/techreports/viewreport.php?report=88)提供高效位置索引方法，但哈希只解决查表，不定义语义等价。本项目必须先生成规范投影，再哈希，并在关键缓存中保留完整键或二次摘要校验碰撞。

## 推荐的五层记录

| 层 | 内容 | 是否进入规则状态键 |
| --- | --- | --- |
| 静态规则凭据 | rules-v1、atom/hook、卡牌数据、Steamroller packet、Host 提交和数据版本 | 以凭据摘要进入 |
| 规范规则状态 | 当前方、绝对轮次/阶段、棋盘、模型生命周期、资源、状态、持续效果、场景、待结算窗口 | 是 |
| 搜索上下文 | 终局种子、胜利相对层、模式、效率下界、剩余深度和未解决义务 | 不进入规则状态键；进入搜索缓存键 |
| 路线标签 | 概率质量、路径成本、主动兑换、容错、对手覆盖、未解析质量 | 不进入状态键；在节点保存 Pareto 标签集 |
| 解释与训练来源 | 战术意图、报告文本、来源动作、严格回放凭据、训练轨迹归属 | 不进入状态键；永不因汇合丢失 |

由此生成三个不同标识：

1. `rulesStateKey = hash(staticReceipt, canonicalRulesState)`
2. `searchMemoKey = hash(rulesStateKey, searchContext)`
3. `routeLabelKey = hash(incomingRoute, costVector, probabilityReceipt, provenance)`

不能用一个 `stateHash` 同时承担这三种职责。

## 规范规则状态

### 必须保留

- 绝对时间：轮次、行动方、阶段、control step、激活前奏和所有未结算窗口/continuation stack。
- 棋盘事实：精确位置、朝向、底座、地形、模板、动态障碍和场景物件状态。
- 完整编制中的每个模型：在场、摧毁、boxed、移除、dormant、replacement、召唤来源等生命周期，而不是仅保留存活模型。
- 生命与系统损伤、Focus/Fury/Soul/Corpse/Hunger 等资源。
- 每激活、每回合、每局使用状态，feat 与动态获得/失去的规则。
- 控制者、战斗群、单位、附件、替换、锚点和目标关系。
- 持续效果、upkeep、状态标签、期限和来源中会影响解除或后续触发的部分。
- Steamroller 计分值、计分历史、攻守方、计分窗口、场景元素和终局相关状态。
- 已作出的规则选择和会改变未来动作空间的卡牌/部署选择。

### 移出动态载荷但纳入静态凭据

- 完整卡牌文本、规则原子定义、覆盖 family 列表和分析 schema。
- 没有动态变化的武器、法术和基础属性快照。
- Host 路径、生成时间和数据导入来源。

如果运行时允许卡牌快照在同一局中变化，则这些字段不能移出；第一版应禁止这种输入并 fail closed。

### 只保留为路线来源

- “为什么这么走”、主动兑换意图和策略计划。
- 搜索分数、候选排名、生成器名称、LLM/skill 来源。
- 之前经过但已完全状态化、且不再影响未来的动作文本。

## 时间模型

规则时间和搜索时间必须并存，但职责不同：

- 规则时间：绝对 `round/activeSide/phase/step/window`，由 Host 判断 Steamroller 计分、持续效果、每回合重置和终局。
- 搜索时间：`turnsBeforeTerminal/activationsBeforeTerminal/eventsBeforeTerminal`，用于反向迭代加深和报告。

终局种子必须声明候选绝对发生时点。相同的“胜利前一回合”在 Defender 第 2 回合和第 6 回合具有不同计分与轮次规则，不能仅靠相对层表示。搜索应枚举允许的绝对终局时点，再在每个时点内向前驱层回归。

## 反向分支汇合规则

反向搜索从终局向前驱展开。两条不同终局证明可能沿不同动作后缀，反向回到同一个更早的 `rulesStateKey`。此时：

- 从这个更早状态继续寻找其前驱的规则计算可以共享；已经认证的状态行为和 strict 转移结果也可以复用。
- 两条“该状态到终局”的证明后缀不能合成一条。各自的概率质量、路径代价、主动兑换、战略意图、来源和 strict receipt 必须保留为独立出边/标签。
- 只有一个标签在所有保留维度上支配另一个标签，且概率统计不需要被支配路线的独立质量时，才可删除被支配标签。
- 来自不相交 Chance 事件的概率不能因状态汇合而丢失；共享后继求值，概率仍沿入边聚合并防止重复计数。
- 如果搜索门槛依赖已经花费的路径成本，则缓存键必须包含对应搜索上下文，或节点必须对每个非支配标签分别评估，不能复用一个无条件值。

这里共享的是“同一个状态还能由哪些更早状态产生”的反向展开，不是把终局后缀当成相同。若当前节点仍只是未完全落地的符号义务，而不是完整规则状态，则必须把义务和终局上下文放入 `searchMemoKey`，不能仅凭 `rulesStateKey` 汇合。

## 三档等价

1. **严格相同**：同一静态凭据、规范动态状态逐字段相同。可硬汇合。
2. **已证明商状态**：模型置换、镜像或动作偏序已经通过规则行为证明。可在证明适用范围内硬汇合，并保存反展开映射。
3. **启发式相似**：拓扑、阵型、距离桶或数值容差相似。只能用于聚类、排序和候选提议。

浮点位置不得用 epsilon 近似作为第一档硬汇合。应使用 Host 规范化后的确定性数值编码；若未来引入网格/距离商，必须作为第二档单独证明。

## 实现建议

新增独立于搜索器的深模块：

- `buildStaticRulesReceipt(hostReceipt, packet, dataReceipt)`
- `projectCanonicalRulesState(normalizedState)`
- `buildRulesStateKey(receipt, projection)`
- `buildSearchMemoKey(rulesStateKey, searchContext)`
- `mergeRouteLabel(paretoLedger, routeLabel)`

投影 schema 采用显式允许列表，不依赖删除几个已知 `metadata` 字段。rules-v1 新增任何规范字段时，schema parity verifier 应先失败，迫使维护者分类该字段。

## 验证门

1. normalizer 幂等：重复规范化不改变投影和键。
2. 输入别名一致：16 个已知兼容入口生成相同规范投影。
3. schema parity：Host 新增顶层、模型、地形、场景或窗口字段时必须显式分类。
4. 行为指纹：同键状态的合法动作、reject 原因、一步转移、终局和 Chance 质量一致。
5. 历史回归：feat、回合使用、计分历史、移除阶段和 pending window 不得误汇合。
6. 路线保留：主动兑换和普通路线汇合后共享后继，但报告、成本、概率与训练来源仍各自可恢复。
7. 对称反展开：商状态路线能还原成原模型身份并通过 strict replay。
8. 碰撞防护：哈希命中后验证完整规范键或二次摘要。

## 用户决定

1. **已确认**：接受五层记录和三个独立键，规则状态、搜索上下文、路线来源不能混成一个对象。
2. **已确认**：同一更早规则状态共享继续向前驱展开的底层计算，但保留从该状态通往终局的不同证明后缀，并逐条 strict 正向认证。
3. **已确认**：完整编制生命周期常驻状态，包括已摧毁、boxed、移除、dormant 和 replacement 模型。
4. **已确认**：只有严格相同与已证明商状态可硬汇合，阵型、拓扑和距离相似仅用于排序。
5. **已确认**：每个终局种子同时指定绝对 Steamroller 时点和胜利相对层。
