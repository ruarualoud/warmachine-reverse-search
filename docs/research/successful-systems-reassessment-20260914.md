# Warmachine 搜索器成功项目复核与方案重评估

**日期：** 2026-09-14  
**问题：** 是否已有项目成功解决了与 Warmachine 相近的严格规则、连续几何、随机结果、对手回应、长时程和军表组合搜索；这些证据是否支持当前反向搜索与策略压缩路线。  
**结论性质：** 基于论文、项目官方页面和源码说明的架构裁决，不是 Warmachine 策略值证明。

## 执行结论

没有找到一个已经成功覆盖下列全部条件的项目：

- 大量可更新的卡牌特规；
- 连续桌面位置、路径碰撞、LOS 和模型遮挡；
- 多模型 Unit、复杂激活顺序和回合内反应；
- 骰子概率与对手最坏回应；
- 军表、部署和多回合策略同时求解；
- 同时要求规则严格、路线可解释并保留全部有效策略类。

最接近的直接项目 `4Hammer` 也只实现了 Warhammer 40K Combat Patrol 的 `6/35`
势力和 `22` 个单位，把桌面量化为一英寸方格，删除障碍、三维和次要目标；作者报告神经网络与
LLM 尚未表现出良好的战略能力。因此，业界和学界当前没有一条可直接复制的“全量微缩战棋
最优求解”成功路线。

不过，多个成功系统分别证明了我们所需的子结构：

1. **严格有限随机博弈可以求值和合成策略。** PRISM-games 已在机器人、UAV、城市驾驶等
   有限模型上计算对抗保证、概率可达、期望代价和多目标 Pareto 策略。
2. **目标反向约束能有效引导无限连续动作。** HBF 用简化空间中的反向可达约束选择候选，
   但最终仍从真实初态正向执行，并只在采样器满足条件时获得概率完备性。
3. **巨大博弈可以获得很强的近似策略。** Libratus、DeepStack、AlphaStar、DeepNash 和
   microRTS 都依赖分解、局部重求解、策略种群、学习值函数或动作脚本；它们不枚举全部策略，
   也不提供原始连续游戏的全局完备证明。
4. **反向数据库只在强收敛离散游戏中获得过完整成功。** Chinook 借助残局逆向数据库和
   正向证明搜索弱解西洋跳棋；其十子数据库涉及约 `13` 万亿状态并压缩为 `215 GB`。这不能
   直接外推到棋子可连续移动、状态可能增长且规则持续更新的 Warmachine。

所以应保留“反向搜索优先抓取有效目标路线”的思想，但必须改变其数学角色：

> 反向搜索是目标义务、候选动作和乐观上界的生成器；真实可达性、对手回应和最终值由当前
> Strict Host 的正向重放、随机博弈求值及反制迭代来证明。

## 直接相似项目的关键事实

### 4Hammer 不是现成答案

4Hammer 的工程边界与我们高度相似：无界面运行、合法动作枚举、动作验证、状态/轨迹序列化、
图形回放，以及把完整状态和合法动作交给 LLM。它值得参考的地方是执行器和代理接口分层。

但其论文同时给出不能忽略的限制：

- 只实现 `6/35` 个 Combat Patrol 势力、`22` 个单位；
- 未实现与这些单位无关的规则；
- 把连续 `44×30` 英寸桌面变为一英寸网格；
- 删除三维、障碍和可选次要目标；
- 作者没有观察到神经网络或 LLM 在战略层表现良好；
- Gemini 能读懂部分局面，但动作质量“相当差”；
- 超人级玩法被列为未来工作。

这说明我们的 Strict Engine、动作枚举、轨迹和回放工作不是多余的；它也是目前直接相似项目
没有跨过去的门槛。反过来，它不能为当前策略压缩或初态胜率背书。

来源：
[4Hammer 论文](https://arxiv.org/pdf/2505.13638)、
[4Hammer 项目](https://github.com/rl-language/4Hammer)

### Atlatl 是决策实验台，不是完整兵棋求解器

NPS 的 Atlatl 提供无头自弈、人机界面、回放、可配置目标和固定随机种子的实验基础设施，
并在小型六角格场景研究 RL、层级 RL 和多模型代理。这与我们的“严格模拟器 + 搜索器 + 报告”
分层相近。

但其论文明确把复杂长时程兵棋的普遍超人能力列为未解决目标；基础实验常用 `5×5` 六角格、
两到四个单位、一个目标点和简化评分。成功的是实验方法与局部代理，不是完整复杂兵棋的最优解。

来源：
[Scaling Intelligent Agents in Combat Simulations for Wargaming](https://arxiv.org/pdf/2402.06694)、
[Atlatl 项目](https://github.com/cjdarken/atlatl-public)

## 各类成功到底证明了什么

### 形式化求解成功：先声明有限模型

PRISM-games 的机器人协调例子把双方、随机移动失败、碰撞、目标和时间奖励编码成有限并发随机
博弈，再求一方可保证的到达概率、有限步概率和期望时间。城市驾驶案例也在编码后的停止博弈上
构造多目标策略。

这为我们提供了正确的最终求值语义：

```text
我方状态 = max
对手状态 = min
骰子状态 = 概率加权
抽象未分辨状态 = 同时保留 lower / upper
```

它没有证明任意连续 Warmachine 局面可以自动变成小型有限图。`Q_rule` 的完备划分、动作域、
对手回应和 Chance 守恒仍必须由 Ticket 20 提供。

来源：
[PRISM-games 案例集](https://www.prismmodelchecker.org/games/casestudies.php)、
[机器人协调案例](https://www.prismmodelchecker.org/casestudies/robot_coordination.php)、
[城市驾驶多目标合成](https://www.prismmodelchecker.org/papers/qest13.pdf)

### 反向引导成功：不等于纯反向求值

HBF 面对无限连续动作时，先在简化约束空间从目标反推可能有用的动作，再从完整真实初态正向
搜索和做碰撞可行性检查。其反向图刻意是解集合的上近似，因此不会把未发现的具体动作直接
当作不存在；概率完备性还依赖每个连续采样器本身满足完备条件。

这与我们需要的路线几乎一致：终局义务用于聚焦，Host 正向执行用于证明。但 Warmachine 还多了
对手量词和 Chance，所以每层反推都必须保留对手可破坏分支，不能只保存达成目标的合作路径。

来源：
[Backward-Forward Search for Manipulation Planning](https://lis.csail.mit.edu/pubs/garrett-iros15.pdf)

### 超人表现成功：依赖局部重求解和策略种群

Libratus/DeepStack 没有预展开扑克的全部 `10^161` 级决策点；它们在离线近似策略之上，对当前
相关子博弈持续重算，并用学习值估计叶子。AlphaStar 也不保留单一路线，而是训练不断产生反制
的策略联盟，最后从联盟的 Nash 分布选策略。PSRO 把这一模式抽象成：从小策略集开始，计算收益
矩阵，针对当前混合策略产生新回应，再扩展受限博弈。

这支持我们把“军表 + 部署 + 阵型 + 回合计划”视为策略级对象，而不是把每个坐标动作直接塞入
一个全局树。它也要求保留非传递反制，不能按单一平均分或单一代表删除策略。

来源：
[Libratus](https://www.ijcai.org/proceedings/2017/0004.pdf)、
[DeepStack](https://poker.cs.ualberta.ca/publications/17science.pdf)、
[AlphaStar](https://www.nature.com/articles/s41586-019-1724-z)、
[Policy-Space Response Oracles](https://mlanctot.info/files/papers/nips17-psro.pdf)

### 精确逆向成功：依赖收敛终局和巨大数据库

Chinook 的逆向残局库替换了末端启发式值，但完整证明还需要从开局向前的证明树和独立复核。
十子残局库约 `13` 万亿位置、压缩后 `215 GB`；即便如此，团队曾因错误排除部分位置而重算。

Warmachine 的模型位置连续、状态不一定随时间单调减少，revive、召唤、资源、持续效果和场景
计分还会扩大或改变状态。因此可复用的不是“全局逆向表库”，而是小型收敛残局核、内容寻址
转置和独立证明复核。

来源：
[Chinook 求解论文索引](https://webdocs.cs.ualberta.ca/~chinook/publications/solving_checkers.html)、
[十子残局数据库](https://webdocs.cs.ualberta.ca/~jonathan/publications/ai_publications/databases10.pdf)

## 对当前方案的重新裁决

### 保留的部分

1. 从刺杀、得分和交换结果建立终局义务。
2. 由规则原语反推必要资源、位置关系、激活顺序和前置状态。
3. 用反向约束显著偏置连续动作采样。
4. 每条候选路线都回到 Strict Host 正向重放。
5. 保留所有被剪枝、未展开、概率质量和对手回应的可追溯账本。
6. 在声明过的有限查询域中，用交替博弈、Chance 和上下界进行认证。

### 必须放弃的部分

1. 不再追求对“完整 Warmachine、所有军表、所有连续位置、无限时域”的全部有效策略商证明。
2. 不再把首屏动作形状、动作数量、期望伤害或一个代表分支当作策略等价。
3. 不再让纯反向合作路线直接产生胜率；未展开对手回应时上界不能成为值。
4. 不再把 LLM/ranker/skill 的低评分当硬剪枝证书。
5. 不再把旧 Host 回执下的搜索结果续签到新规则器。

### 新的双轨产品合同

#### A. 有界认证求解器

输入必须固定：规则与卡牌回执、地图、军表、部署域、先后手、信息模型、回合上限、终局和目标。

处理链：

1. Strict Host 枚举/验证具体动作；
2. 反向义务产生候选连续区域和必要动作；
3. 正向 Strict 见证证明真实可达；
4. Max/Min/Chance 构造有限随机博弈；
5. 精确重访、可证明对称、双人顽固集和概率交替双模拟分别签证；
6. 粗抽象保留上下界，CEGAR 用反例拆分；
7. 只有 `unresolved=0` 才发布该查询域的精确值或完整策略类。

它能给出严格结论，但结论只属于声明过的有限域。

#### B. 实用策略顾问

处理对象不是全部原子动作，而是可解释的策略 policy：军表、部署模板、阵型、目标选择、资源计划、
刺杀包、得分包和应对脚本。

处理链：

1. 反向搜索、现有 skill、人工种子和 LLM 只负责提出 policy；
2. Strict Host 正向自弈计算 policy 对 policy 的收益分布；
3. 用 PSRO/Double Oracle 维护收益矩阵和混合策略；
4. 用局部 MCTS/持续重求解寻找当前种群的反制；
5. 新反制回流种群，直到预算用尽或经验 exploitability/区间达到门槛；
6. 报告胜率置信区间、对手覆盖、反制循环和未决策略质量。

它可以成为选手指导和军表比较工具，但只能宣称“在已发现策略种群、地图分布和预算下的经验
最优/稳健”，不能宣称全游戏最优。

### LLM 的正确位置

LLM 不参与合法性、概率守恒、等价或胜率证明。它只适合：

- 从卡牌与局面提出目标义务和 policy 候选；
- 为搜索排序，不删除未证明分支；
- 解释已由 Host 执行的路线、失败和反制；
- 生成下一轮需要挑战的策略假设。

规则执行、动作所有权、Chance、状态转移、终局和证书全部由代码负责。

## Ticket 影响

### Ticket 23

目标不变。规则语义、执行器和跨运行时认证仍是所有搜索结果的前置条件。当前 Host 变化后，
旧 continuation 数据只能作性能和缺陷证据。

### Ticket 20

`Q_rule` 不再承担“把完整游戏压成很小”的隐含目标。它只需对一个声明有限查询域给出：完整动作
参数轴、连续区域债务、Unit、回应、Chance、终局观察和后继稳定性；不能闭合的部分进入上界。

### Ticket 22

当前 142 类和七个形状组只保留为候选调度。下一版按以下顺序签发独立证书：

1. 精确内容重访；
2. 规则/地图自同构；
3. 双人顽固集；
4. 概率交替双模拟；
5. 可采纳上界支配；
6. 未决补集挑战。

同时增加 policy 级 PSRO 收益矩阵；状态级安全压缩与 policy 级经验选择不得共用一个
`equivalent` 标志。

### Ticket 21 与报告台

Ticket 21 的局部反制路线继续有效，但必须绑定新 Host 重建。报告台应同时显示：

- 有界认证区间与未决分母；
- 当前策略种群的经验胜率和置信区间；
- 每个 policy 的最强已知反制；
- 可展开到 Strict 原始动作的具体路线；
- 哪些结论来自证明，哪些来自抽样。

## 可行 Demo 门槛

### 微型认证域

选择一个可以不开任何 reduction 全量穷举的双人随机场景，比较：

- reduction 关闭和开启后的上下界/精确值；
- 被合并状态的双方动作对应和 Chance coupling；
- 被 POR 删除的激活排列；
- 人工注入反例能否触发 CEGAR 拆分；
- 全部原始策略类是否仍能从报告展开。

这是“压缩不丢策略”的唯一首个有效实验。

### Cryx 对 Fane 任务域

固定版本、Steamroller 地图集、Cryx 约束军表和 Fane 候选集后：

1. 用反向义务生成刺杀、得分、交换和阻挡 policy；
2. 正向 Strict 自弈建立收益矩阵；
3. PSRO 逐轮加入双方最佳已知反制；
4. 对关键当前局面做局部重求解；
5. 输出地图/部署/军表条件下的区间、经验胜率、反制覆盖和未决质量。

这个 Demo 可以论证“搜索器产生有用、可执行、可反驳的策略指导”，但在有限域未闭合前不能论证
“全部有效策略已覆盖”。

## 最终判断

当前项目不是走错了“反向”这个方向，而是之前赋予了反向结果过强的证明含义。成功项目共同采用
的模式是：

```text
严格或可信模拟器
  + 目标/抽象/学习提供搜索偏置
  + 当前局部的真实正向执行
  + 对手反制循环
  + 明确的证明边界或经验评估
```

因此，新方案比纯正向更容易命中稀疏有效终局，比纯反向更不容易接受不可达或合作型伪路线；
它的证据不是“理论上听起来合理”，而是 HBF、PRISM-games、扑克子博弈求解、AlphaStar/PSRO
策略种群和直接微缩战棋项目的共同工程边界。
