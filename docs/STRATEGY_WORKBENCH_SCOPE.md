# 策略工作台：用途、可行性与开发缺口

日期：2026-09-05。本文明确产品目标和验收边界，不宣称功能已经完成。具体开发状态仍在对应ticket内维护。

## 三种查询

| 用途 | 固定输入 | 搜索自由度 | 输出 |
|---|---|---|---|
| 两势力对抗优化 | 势力、合法点数/配装范围、场景地图、选表时序与对抗目标 | 军表、配装、部署及双方后续策略 | 条件排名、互相克制关系、部署与操作分支、值区间 |
| 当前局面指导 | 精确当前状态、我方视角、当时可见信息、目标与剩余时域 | 从当前窗口开始的合法动作及双方应对 | 下一动作、替代方案、最不利回应、后续变招和证据 |
| 达到指定目标局面 | 合法起点或起点域、目标谓词和期限 | 通往目标的动作/策略 | 可达路径、条件成功概率或对抗保证，按查询模式分别显示 |

当前局面是起点，目标局面是终点约束，不可混用。只要求到达一个指定局面时，优化的是该目标的可达概率，不自动称为整局胜率。两势力模式的目标默认包含声明时域内的全部合法获胜方式，不把几个根代表当作全部获胜方式。

## 可行与不可承诺的部分

同一Host执行器、反向约束、正向见证、策略DAG和概率界可以服务三种查询，方向无需推倒重来。给定已经证明有限、规则闭合且信息语义明确的任务域，可以用随机博弈的可靠上下界计算对抗值；预算未足时先输出可靠区间。[PET2方法依据](https://link.springer.com/chapter/10.1007/978-3-031-65633-0_16)

这不保证所有100点军表、全部物理连续位置和任意长时域都能在可接受时间内穷尽。反向必要条件和目标相关剪枝可减少探索，但是否足够要在相同覆盖分母下实测。有限域也可能很大，不能预先承诺实时响应或必定收敛。

“最优”必须绑定规则版本、军表/动作域、地图、时域、信息和目标。当前找到最好候选、声明域内有误差界的近似最优、声明域内精确最优分别标注。区间重叠时保留多个未被排除候选。

两势力可能不存在一张处处最好的军表。固定对手表的最佳回应、双方先后选表、同时选表是不同问题；同时选择的池内分析可能需要混合方案，不能把逐行最大值叫双方均衡。地图/先手不由玩家选择时按声明分布或逐格报告，不从样本频次推断真实概率。具体目标必须像概率可达/奖励查询一样明确。[PRISM-games目标区分](https://www.prismmodelchecker.org/games/properties.php)

## 当前代码核对

- 已有：精确配装构筑与有限合法池、反向终局/历史路线、Host执行认证、候选参数域的部分实现、OR/AND/Chance值代数、有限策略商验证、外存恢复与回放界面。
- `custom-matchup-task-v1` 当前主要声明军表、地图、部署和终局回合域。
- `search-console-contract-v1` 当前种子只接受 `preset_reference` 与 `exact_terminal_root`，终局目标为刺杀/场景得分；未知种子类型会拒绝。输入当前局面与一般目标谓词不是已完成产品入口。
- 现有终局seed禁止注入forwardOracle/opening/intermediateState等答案数据。新增当前局面模式应建立独立的受校验输入合同，不能删除这些反向验证隔离要求。
- 跨回合完整回应、一般连续域、生产策略商和当前规则认证仍有缺口。没有现成的完整“输入任意对战场面 -> 可信最优建议”链路。

## 局面输入与更新

使用桌面导出的结构化状态或显式编辑的假设状态，复用已有Layer3/Host转换。所需信息包括精确模型身份/配装、位置/朝向/底盘、Unit成员、损失与分区伤害、资源、状态/持续效果、已用feat、当前窗口/激活历史、待处理选择、历史计分及地图来源。

进入搜索前检查会影响本任务未来转移的必需字段。缺失时请求补充、按显式假设分析或保留未知；不能静默当作满血、零资源或未使用能力。仅凭截图不能认证完整规则状态。人工移动不合法或历史不确定时应指出问题，不把手工摆放强行改成另一局面。

从当前局面给条件建议不要求重新证明它从部署可达；报告写明这是输入状态条件下的分析。若用户要求完整历史证明，才另走06/07/19。每个建议绑定输入状态、Host、查询与时域指纹；新动作或规则更新使旧建议过期，允许复用依赖未变的后继计算。

## 策略与选手复盘

建议应输出下一动作及其后续分支，不只是一串固定动作：目的、合法参数/路线、资源消耗、对手可用反制、我方变招、胜利/目标概率界，以及没有选其它动作的证据。终局判定由Host负责，已真正获胜的状态停止展开。

选手复盘固定**动作前**的状态、目标和可获得信息，将实际合法动作与替代动作放在同一任务下比较。不能在选择前利用后来发生的骰值；非法/缺参数的人工动作先做规则诊断，不能计算为“策略较差”。

可复用21的动作值区间衡量决策损失。若最优值为 `[L*,U*]`，实际动作值为 `[La,Ua]`，则损失界为 `[max(0,L*-Ua), max(0,U*-La)]`。前提是两个界对同一任务有效、实际动作已纳入合法域；下界为0时不能断言该动作一定犯错。该公式是区间运算的设计推论，待验收，不是目前已运行的评语功能。

这里比较的是该步之后仍按相应最优续策行动的值，不把选手整局所有决策损失简单加总为“损失的胜率”。反复更新建议时也要保留原查询的绝对截止时点；用户选择滚动时域时另记任务语义，不能静默把目标期限每步向后挪。

近似最优建议需附误差证书：选中策略的可靠下界为Lb，全部候选（含未展开部分）的可靠上界为U*，只有 `U*-Lb <= epsilon` 才可称在该域内epsilon最优。单纯预算到期、几轮排名没变或候选评分高不是收敛证明。已有认证门未通过时只展示研究候选，不提升声明。

第一阶段只读导入、分析和复盘，不自动控制对战房间。实时房间跟随、自动落子及线上对战集成仍属于后续集成工作；本轮不开发或重启它们。

| 工作 | 归属 | 最小端到端验收 |

| 选手建议/决策复盘 | 09、10、21 | 实际动作对照；坏骰子不被当作前一决策错误；误差未闭合时不硬排名 |
| 建议过期与复用 | 12、15、17 | 新状态使旧建议过期；中断恢复、重复导入不重复计数 |

不新增全局ticket，也不把历史已完成工单重开；上述是开放工单的明确集成工作，03等旧基础仅在集成时扩展。每一模式先完成一个小型人工场景的真实全链路，再进入三族真实军表场景。性能用实际耗时和区间收缩记录，未实测前不设“秒级实战分析”承诺。
