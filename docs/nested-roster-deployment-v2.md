# 军表、部署与模型历史嵌套搜索 V2

## 搜索边界

本层把反向终局搜索接到两个有限开局空间：

1. 固定军表模式：在已认证的双方军表上枚举先手和有限阵型库，输出合法精确部署。
2. 固定阵营模式：先从内容绑定的有限军表提议池选取规范军表，再嵌套军表对、先手和阵型对。

当前 Cryx/Fane 来源池各含 96 条军表。来源生成器使用精确点数动态规划、结构束剪枝和 MAP-Elites 式多样性归档；最终候选由 `WarmachineForceBuilder` 检查 100 分、FA、模块选择、挂接、必需关系和战斗群。它不是随机均匀的全阵营军表枚举，也不穷尽所有合法军表。

任何随机背包、动态规划或学习型构筑提议器都可以接入同一接口，但必须先形成有限来源池、绑定文件内容哈希、列出每个合法规范军表身份，并保留生成/拒绝/剪枝分母。搜索层不能仅凭调用者提供一个“合法”布尔值接受池外军表。

## 军表身份与质量账

规范军表身份包含阵营、军队、Leader、总分，以及排序后的卡牌来源、实例名、类型、行分、模型数、模块、挂接与战斗群关系；临时 `entryId` 和输入顺序不参与身份。等价来源提议合并为一个候选，但别名数量和来源质量相加，不会消失。

每个座位的质量账分为：来源非法、终局能力精确排除、已选择、预算未搜索。双方独立来源质量相乘形成军表对质量，再均分到声明的先手选项和有限阵型对。最终统一记录：

- 来源军表非法质量；
- 终局提议精确排除质量；
- 军表/军表对预算未搜索质量；
- strict 合法部署质量；
- strict 几何拒绝质量；
- 阵型预算未搜索质量。

所有项必须守恒为来源军表对总质量 1。该质量只描述有限提议器，不是所有合法军表或连续部署空间上的概率分布。

## 部署合法性

阵型库只决定 lane、depth、role 和排序先验。精确坐标由 Project D construction Host 的部署 packer 产生，再审计底座完整位于部署区、无重叠、单位连贯和挂接距离。返回 opening 保留军表来源键、先手、阵型、部署证书和审计；需要完整状态时额外物化 rules-v1 state、100 分点数账和每个模型来源账。

## 模型历史

所有模型在每个完整状态检查点中保留独立身份，即使 disabled、destroyed、removed、off-table、休眠或替换。直接与终局义务相关的模型保存每个检查点；只有声明的历史起止范围完整，而且每段包含当前 Host 收据、动作身份、前后规范状态哈希、事件摘要和匹配摘要的 strict 成功收据时，才记为完整历史。

暂时无直接交互的模型保留起止快照、来源、生命周期和可达包络，并可在同单位、同来源、同包络下共享延迟计算。普通 `2×SPD×激活数` 默认只是排序上界，因为额外移动、反应和卡牌规则尚未闭合。只有逐模型移动来源闭合后，位移超过乐观上界才能形成精确不可达反证。

## 能力瓶颈

唯一模型或规则来源默认只提高军表顺序。缺少提供者只有在以下证据同时存在时才可把军表移出当前终局提议宇宙：图层允许硬锁、来源分类闭合、替代提供者已穷尽、乐观能力上界精确、strict 轨迹保存性已证明、没有 wildcard。即使满足，这也是对指定终局义务的精确排除，不是构筑非法。

## 实测

真实 5×5 池中各选择 3 个规范军表，形成 9 对；预算尝试 2 对、双方先手和每边 2 个阵型，共得到 16 个合法部署，0 个几何拒绝。合法 opening 质量为 `0.08`，军表预算未搜索质量为 `0.92`，总质量守恒。固定首对军表的单 opening 含 103 个模型，双方点数均为 100，来源未知数为 0。

103 模型开局中，两名 Leader 仅有部署检查点，因此正确保持“已展开但历史范围未完成”；其余 101 个模型保留延迟包络。另一个真实 rules-v1 strict 近战终局段证明两名 Leader 的前后状态和生命周期可由逐段收据晋升；篡改摘要会退回 unresolved。

可复现证据见 `docs/research/nested-roster-deployment-v2-verification.json`。
